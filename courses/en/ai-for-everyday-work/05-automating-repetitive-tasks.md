## Key ideas
1. **Look for tasks you do often, the same way, with text.** Weekly updates, replies to
   similar questions, meeting notes, product descriptions, reformatting information: these
   are good candidates. Tasks that are rare, unclear or very high stakes are not.
2. **Turn your best prompt into a template.** When a prompt works well, save it with blanks
   to fill in: "Write a weekly update for [team] from these notes: [notes]. Format: 3
   sections, done / next / blocked, under 150 words." Next time, you only fill the blanks.
3. **Keep a small library.** Store your templates where you can find them (a note, a
   document). Improve a template each time an answer needs the same fix twice.
4. **Batch similar items.** Instead of ten separate requests, give ten items in one go with
   one set of instructions, for example "rewrite each of these product names in the same
   style". Check the batch, since one item can go wrong while the others are fine.
5. **Use what your tool offers, carefully.** Some assistants let you save standing
   instructions, reusable setups or recurring tasks. They can save time, but anything that
   runs without you looking still needs a check now and then. Building real automations that
   connect tools usually takes code, which is the subject of the Build with AI course.

## Teaching notes
- Analogy that works: **a recipe card**. The first time you cook a dish you improvise; once
  it works, you write the recipe down so it comes out right every time, and you adjust the
  card when you improve it.
- Demo: ask the learner for one task they repeat weekly. Write a first prompt together, run
  it, fix one thing, then turn it into a template with [blanks].
- Stay tool-neutral: describe features generically ("saved instructions", "recurring tasks")
  and never name products or say which tool has which feature; these change quickly.
- Misconception: "automation means the AI does it alone". Here it means less typing and more
  consistency; the person still reviews the output, especially anything sent to others.
- Misconception: "I need to code to save time with AI". Templates and batching need no code
  and cover most everyday repetition.
- For technical learners, mention that the next step (APIs, scripts, connected tools) is in
  Build with AI, and keep this lesson no-code.

## Check your understanding
1. Which of these is the best candidate for a reusable AI template, and why: a weekly team update, a one-off apology to an upset client, or writing your company's annual strategy?
   Good answer: the weekly team update; it is frequent, follows the same shape and is low-risk, while the others are rare, sensitive or high stakes.
2. What makes a prompt template reusable?
   Good answer: the fixed instructions (format, tone, length) are written once, with clear blanks for the parts that change each time.
3. You batch 15 product descriptions in one request. What should you still do?
   Good answer: check each result, because one item can be wrong or off-style even when the others are fine.

## Exercise
Needs your own chat assistant — free. Pick one task you repeat at least every month. Write a
prompt for it, run it on a real (non-confidential) example, fix what is off, and save it as a
template with [blanks] in a note. Share the template with the tutor.

## Completion criteria
The learner answers the checks correctly and produces one reusable template with blanks for a
task they really do.
