## Brief
Pick a task you do again and again that involves text: the weekly update to your team, a
summary of meeting notes, a reply to a common question, a description for things you sell.
Your goal is a prompt you can copy, fill in and send each time, and that gives you a result
you would actually use.

You choose the task, write the prompt and test it yourself. Your tutor is your coach: it asks
questions, gives a hint when you are stuck and reviews your prompt with you, but it will not
write it for you.

Use real cases for your tests, but never paste personal or confidential information into the
chat app: remove or change names, numbers and anything private first.

## Milestones
1. **Choose the task and what "good" means.** Pick one real task you repeat, and decide what
   a result must have for you to use it as is.
   Done when: the learner names the task, who reads the result, and two or three things that
   make a result good for them (for example length, tone, what it must always include).
2. **Write the first version.** Write a prompt that gives the context, the goal, the audience
   and the format, with clear placeholders for the parts that change each time.
   Done when: the learner shares a prompt that states the task, its context, its audience and
   the format of the answer, and marks the parts to fill in each time.
3. **Test it on three real cases.** Use the prompt on three different real inputs, and compare
   each result with the learner's own definition of "good".
   Done when: the learner has tried the prompt on three different inputs and can say, for
   each one, what was good and what missed, against the criteria from milestone 1.
4. **Improve it and test again.** Change the prompt to fix what missed, one change at a time,
   and run the three cases again.
   Done when: the learner shares a revised prompt, explains which miss each change fixes, and
   the new results are at least as good on all three cases.
5. **Write the instructions for use.** Add a short note to the prompt: when to use it, what to
   fill in, and what to check by hand before using a result.
   Done when: the note says when to use the prompt, what to paste or fill in, and at least one
   thing to check before using the result.

## Coaching notes
- **Coach, do not write.** Never write the prompt, a part of it or a "better version" for the
  learner. When they are stuck, go up a ladder of help: first a question ("who will read
  this?"), then point to the idea that helps ("what format do you want back?"), and only then
  a short example on a different task than theirs.
- **Milestone 1 is the one people skip.** Without criteria, "it looks fine" is the only test.
  If the learner jumps straight to writing, ask what would make them send a result without
  editing it.
- **Common misses.** No audience, so the tone is generic; no format, so the length varies from
  one run to the next; placeholders that are not clear, so they forget to replace one; too
  many changes at once in milestone 4, so they cannot tell which one helped.
- **Tests must differ.** Three inputs that look alike prove little. Encourage one easy case,
  one long or messy case and one unusual case.
- **What prompting cannot fix** (covered in Prompting Basics): if the task needs facts the
  model does not have, or exact numbers, the fix is a check by hand, not a longer prompt.
  Steer that into the note of milestone 5.
- **Privacy** (covered in Using AI Safely and Wisely): if the learner pastes names, client data
  or anything private, stop and ask them to disguise it first. Never repeat it back.
- **Beginners** may need help choosing a task: offer two or three everyday ideas and let them
  pick. **Experienced learners** can add an example of a good result to the prompt, or a
  second prompt that checks the first one's output.
- **Pacing.** The project usually fits one session but can span several. Save notes after each
  milestone so the next session starts where this one stopped. You only see what the learner
  pastes: ask for the prompt and the results instead of assuming.

## Review
1. The prompt gives the context, goal, audience and format that the task needs.
2. The parts that change each time are clearly marked, so the prompt can be reused as is.
3. It was tested on at least three different real cases, and each change answers a miss seen
   in a test.
4. The note says when to use the prompt and what to check by hand before using a result.
5. The test inputs contained no personal or confidential information, or it was disguised
   first.

## Going further
- Do the same for a second task, and notice which parts of your first prompt you reuse.
- Add an example of a result you liked to the prompt, and compare the results with and
  without it.
